Build story · Oct 10, 2026

Roomkit

A Next.js app that turns five answers into furniture picks, an isometric room built from one 3D SVG sprite, and an AI photo of that room.

43 minprompt → reviewed app
43.1Mtokens to build it
$16.25at API pricing
Built by Forge (Claude Opus 5.5) in Empryo · deployed on Ploy
01 · The ask

One prompt, three deliverables

1

Ask 4–5 questions

Room type (living, bedroom, kitchen, bathroom), style, palette, mood, priorities.

2

Pick from an SVG sprite

Up to 6 products as cards around a room scene composed from the same sprite: walls, windows, lighting.

3

v2: photo render

Pick an image model (GPT Image 2.5 and others) to render the room as a photo.

Stack asked for: Next.js · shadcn/ui · Tailwind · AI SDK · LLM Gateway provider. Switchable embedding models or flagship models (Opus 5.5, Fable 5.1).

02 · The sprite

No such sprite existed, so Forge built one

  • Web search found only flat SVG icons (GPL, no bathrooms) or tiny PNG renders
  • Took Kenney Furniture Kit: 140 CC0 3D models incl. walls, windows, doors, floors, lamps
  • Wrote an OBJ → isometric SVG renderer: projection, flat shading, coplanar face merging, pixel-buffer depth ordering
  • 257 symbols · 563 KB · 95 KB gzipped, 2–4 orientations each
  • Wood, fabric, walls, floor, trim are CSS variables → one sprite renders every palette
03 · How it works

Five questions, live preview

  1. Brief: room → style → palette → mood → use and budget, with a live sprite preview that recolours and relights as you answer
  2. Engine: embeddings or a flagship LLM picks 4–6 products from 97
  3. Rules: the same room rules apply to both engines: core pieces, one per category, hosts for TVs and stools
  4. Composer: places pieces on walls, in corners, on surfaces and on the ceiling, then depth-sorts the sprite pieces
04 · Two engines

Switch per run

Embeddings

Brief split into 3 facets (use 45%, style 35%, mood 20%) → weighted cosine vs 97 product embeddings, cached. ~1 s.

OpenAI 3 Small/Large · Gemini Embedding 2 · Qwen3 8B

Flagship LLM

Structured output: products, palette hex codes, a title and a reason per piece. 7–11 s (Gemini 3.1 Pro ~31 s).

Claude Opus 5.5 · Fable 5.1 · GPT-5.5 · Gemini 3.1 Pro · Sonnet 5.5 · GPT-5.4 mini

05 · Result

Cards around the room they compose

Numbered markers link cards ↔ pieces · switch Day / Golden / Evening / Night · every run stays one click away

06 · v2 · Photo render

The sprite scene becomes the layout reference

Scene rasterized in the browser → sent with the prompt to GPT Image 2.5 Sunburst (also Flare, GPT Image 2, Gemini 3 Pro Image, Nano Banana 2.1, Seedream 5.0 Pro, Qwen, Grok, Muse) · ~20–50 s

10 · What broke, and the fixes

Found by testing, not by guessing

  • Reviewer fail: LLM picks skipped room rules → one shared rules function, checked against 2,000 random selections
  • Sprite 404: no error handling → alert + Retry, versioned sprite URL
  • Ploy 500: Next 16.4 crashes OpenNext (preview-props.json, opennext#1355) → reproduced locally in wrangler, pinned 16.3.8
  • Static page: stale build cache made the gate static → verified dynamic route
  • Localhost cookie: a Secure cookie didn't stick on http → set Secure only when the request is https
  • Demo tool: webreel couldn't type → recorded via Chrome screencast + Playwright instead
