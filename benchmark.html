Roomkit · model benchmark · October 12, 2026

Which kind of model should pick the furniture?

10 models in four categories each designed the same 24 rooms through the real /api/design route. A blind panel of 3 judge models scored every design, alongside automatic checks for brief fit, style, budget, cost, speed and repeatability.

Verdict

  • Flagship LLMs and Cheap flash LLMs tie on quality. 82.6 vs 81.9, with overlapping 95% intervals (80.3–84.7 and 79.3–84.3).
  • 7 models are statistically tied with the leader, Claude Fable 5.1: Claude Fable 5.1, Gemini 3.8 Flash, GPT-6.1 Sol, Claude Opus 5.5, DeepSeek V4.1 Flash, GLM-5.3 Flash, GPT-6 Luna Decisions.
  • Best-value LLM in that tier: GLM-5.3 Flash at $0.0023 per design, 79× cheaper than Claude Fable 5.1. Fastest LLM in that tier: Claude Opus 5.5 at 18s median.
  • Decision models are the instant option. GPT-6 Luna Decisions scores 78.9, 4.8 points under the leader, but answers in 0.5s for $0.00056: 38× faster than Claude Opus 5.5, and the same room every time.
  • Embeddings trail. OpenAI Embedding 3 Large scores 67.8. Similarity search can't follow negatives: embeddings broke 4 of 22 "avoid" rules (such as a TV in the no-TV room), LLMs broke 0 of 66.

Method

Engines

LLMs get the brief and a list of room categories, fetch markdown guides for the categories they want with a readCategoryGuide tool, then return a structured room. Embeddings embed the brief as three facets and rank products by cosine similarity. Decision models answer a yes/no question per category and a pick-one question per category, both written from the same guides, in one /v1/decisions call. All engines share the same rule pass (essentials, host pieces, one per category).

Caveats

The judges come from the same families as some contestants (OpenAI, Anthropic, Google); using three and averaging limits self-preference but does not remove it. Embeddings and decision models do not write titles or palettes, which this benchmark does not score. Latency was measured with 6 requests in flight. Errors count failures on the first pass; DeepSeek V4.1 Flash started rejecting forced tool calls in thinking mode mid-run, so the app now retries the guide step with an optional tool call, and those runs were redone. One run per brief, plus 3 runs on 4 briefs for consistency.

Reproduce

Start the app with APP_PASSWORD and LLM_GATEWAY_API_KEY, then run npm run bench:run, npm run bench:judge, npm run bench:report. Raw data lives in bench/results/.
